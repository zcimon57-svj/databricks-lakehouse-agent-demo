HUAWEI GAP

主要差距不是“少一个模块”，而是五处接缝

公开资料能证明产品存在，不能证明它们在同一租户和同一任务里共享对象、权限、状态与证据；这些接缝必须实测。

01

对象接缝

资产、指标、会话、任务、工件和动作是否有跨产品稳定 ID、版本与深链。

02

身份接缝

浏览器用户能否 on-behalf-of 穿透 Agent 与数据服务，并在数据库执行端强制权限。

03

语义接缝

DataArts 中的指标、Join 与治理策略能否被 DAS/RDS 和外部 Agent 直接复用。

04

工具接缝

内嵌入口和外部 Agent 是否共用权威 API/Tool，而非各自复制 Prompt 和权限逻辑。

05

证据接缝

一次任务能否贯通 Query ID、SQL、来源、新鲜度、策略、Artifact、Eval、Audit 与 Cost。

不是结论

“DataArts 已经覆盖，所以数据库只接一个 Connector”——公开资料不足以证明。

也不是结论

“数据库部门应重做完整数据智能平台”——现有证据同样不支持。

当前假设

三个领域权威加共享控制面，以一条业务旅程验证组织和产品边界。

HUAWEI PLAN · 待验证方案

不是重做一个全栈平台，而是把三个领域权威连成一条客户旅程

当前优先验证“双平面联合产品”：前台允许从 DataArts、DAS/RDS 或企业门户进入；后台由统一对象、最终用户身份、策略、任务状态、工件和 Trace 保证连续。PostgreSQL 先承担首个数据库执行验证，多引擎在 Gate 之后扩展。

PRODUCT OWNERSHIP

四个可选方向，不在验证前锁死组织答案

选项不是四套重复建设。G1–G6 的证据将决定统一入口和共享控制面由谁拥有、哪些能力留在领域产品、商业包装如何形成。

A

数据库独立新产品

RDS/DAS 拥有入口、语义、Agent 和运营闭环。

  • 优点：数据库场景闭环快
  • 风险：重复治理、BI 与 Agent 平台
  • 适用：跨产品复用被验证为不可行
B

DataArts 主导迭代

DataArts 统一入口与智能分析，数据库提供 Connector 和诊断工具。

  • 优点：复用数据治理与 BI
  • 风险：数据库执行深度和运维闭环不足
  • 适用：对象、OBO 和工具平面已贯通
C · 当前优先验证

双平面联合产品

DataArts 管数据语义，RDS/DAS 管执行，AgentArts 管编排，共享控制面串联。

  • 优点：保留领域权威、减少重建
  • 风险：跨团队责任和 SLA 最难
  • 条件：必须通过 G1–G6
D

联邦能力包

不建新总入口，以标准 API/Tool、身份、工件和评测包嵌入各产品。

  • 优点：组织扰动较小
  • 风险：客户旅程仍可能碎片化
  • 适用：统一入口商业价值不成立

DECISION GATES

每个 Gate 都要拿到可以否决方案的证据

当前 Gate 是决策验证，不是伪装成“阶段”的固定开发路线。无法实测的能力保持 Unknown，不能用产品文档或原型图自动判定通过。

G1

对象连续性

跨 DataArts、AgentArts、RDS/DAS 的稳定 ID、版本、引用和深链。

输出：对象映射 + 一条实测链
G2

身份与权限

最终用户 OBO、服务身份、策略决策和数据库执行端强制。

输出：正向/越权用例 + 审计
G3

语义与正确性

指标、Join、时间、状态口径复用，并对 Golden Questions 严格比对。

输出：评测集 + 结果真值
G4

工具与动作

内嵌和外部入口共用 Tool/API；异步、幂等、预演、审批和验证。

输出：能力合同 + 动作证据
G5

运营与保障

任务、SQL、策略、Artifact、Eval、Audit、Cost 和失败恢复共享 Trace。

输出：端到端 Trace + 故障演练
G6

商业与组织

客户是否为完整工作流付费，归属、RACI、SLA 和成本是否可承接。

输出：设计伙伴证据 + 决策稿
通过

确定产品归属、P0 模块、目标架构、OKR 与分阶段路线。

部分通过

缩为数据库能力包或 DataArts 插件，保留已验证的领域权威。

不通过

停止大平台建设，只做高价值专业工作台与标准工具接口。

BUSINESS STORIES

先卖业务结果，再解释背后的 Agent 与数据库

每个故事都必须展示：谁发起、用了哪些对象、策略在哪里执行、产出什么工件、业务如何继续、什么动作必须审批。

01 · 经营分析

从“为什么毛利下降”到可发布的经营工件

区域负责人追问渠道、品类和时间窗口，系统复用权威指标与 Join，保存分析工件并发布到看板。

客户买单点
减少取数等待与口径争议
数据库责任
可复算查询、新鲜度与负载保护
02 · 智能售后

从退款异常到有证据的客户处理建议

联查订单、退款、客户、工单与政策，生成受影响客户清单、证据和建议；退款与发信单独审批。

客户买单点
缩短首答时间，提升一致性
数据库责任
实时状态、历史联查和安全查询
03 · 业务影响诊断

从“结算变慢”到业务与数据库共同时间线

应用 Owner 关联成功率、延迟、慢 SQL、等待、告警、变更和拓扑，形成事故证据包和修复提案。

客户买单点
降低损失窗口，而非只省 DBA 时间
数据库责任
引擎事实、诊断、预演和动作验证
04 · SaaS 内嵌

伙伴不用重建 NL2SQL、权限和审计

伙伴应用带最终用户与租户上下文调用 Tool/API，获得同源语义、任务状态和证据，而不是共享高权限连接。

客户买单点
更快给自身客户提供数据智能
数据库责任
隔离、配额、SLA 与稳定错误契约

EVIDENCE BOUNDARY

把“看见了”与“建议做”分开

  • [工作区实测] 只覆盖本项目在 Databricks Free Edition 中实际观察和验证的路径。
  • [官方资料研究] 证明公开可查的产品能力和入口，不证明目标账号、区域、版本或跨产品打通。
  • [分析推断] 用于建立市场基线和差距优先级；评分不是权威排行。
  • [方案假设] 双平面、共享控制面、UI 原型和后续模块都必须通过 G1–G6，不能写成现有能力。
  • 所有业务数据为确定性合成数据；项目未连接或修改任何生产数据库，也不包含登录凭据、Cookie、Token 或组织标识。
