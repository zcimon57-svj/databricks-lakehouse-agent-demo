TARGET HYPOTHESIS

三个领域权威，不等于三个孤岛

统一入口可以放在 RDS/DAS、DataArts 或企业门户；它必须是可替换的壳。真正不可分叉的是共享控制面和领域权威合同。

DATAARTS / BI

数据与语义权威

拥有资产、Owner、分类、血缘、指标、维度、Join、业务口径和分析工件；对外提供版本化对象合同。

AGENTARTS

任务编排权威

拥有 Plan、工具路由、模型路由、异步状态、重试、Handoff 和多 Agent 协作；不复制数据库权限真相。

RDS / DAS

数据库执行权威

拥有 PostgreSQL 引擎事实、安全查询、负载预算、诊断上下文、预演、审批后动作和结果验证。

SHARED CONTROL

跨产品共同真相

Canonical IDs、OBO、策略决策、Task/Artifact/Action State、Trace、Eval、Audit、Cost 和稳定失败合同。

PRODUCT MODULES

产品方向不是一张大图，而是六个可验收模块

优先级是当前方案假设：P0 先证明对象、身份、语义和安全执行；P1 再形成工件、评测与外部工具；动作自动化最后进入风险 Gate。

P0 · M0统一任务壳
用户为什么需要

从 DAS 的告警、DataArts 的指标或企业门户进入，都能继续同一个任务，不用在多个产品间复制问题和截图。

具体补什么
  • Conversation / Task ID 与跨产品深链
  • 结构化结果、证据、Artifact 和下一步动作
  • 入口只持有视图状态，不私有权限与语义真相
做到什么程度

同一任务可从 DataArts 跳到 DAS 再返回，用户、对象、时间窗口、执行和工件引用不丢失。

P0 · M1共享对象与身份控制面
用户为什么需要

业务用户和外部 Agent 看到相同权限结果；审计能回答“谁以谁的身份，对哪个对象做了什么”。

具体补什么
  • 跨产品 canonical ID / version / owner
  • IAM OBO / purpose / tenant / service identity
  • 统一策略决策接口与执行端强制、审计关联
做到什么程度

至少通过正常、越权、对象改名、权限撤销和跨入口五类回归；Prompt 不能覆盖策略判定。

P0 · M2语义与可信分析合同
用户为什么需要

“已完成退款”“毛利”“P1 未解决”在问答、Dashboard、API 和 PG 查询中是同一个口径。

具体补什么
  • 指标、维度、Join、同义词、时间与状态规则
  • NL2SQL / 可信查询 / 业务说明 / 引用
  • Golden Questions、严格结果真值与语义版本回归
做到什么程度

一个领域先达到可版本、可引用、可评测、可追溯；不以“SQL 能执行”替代结果正确。

P0 · M3PostgreSQL 执行与诊断平面
用户为什么需要

实时订单状态与数据库风险能安全进入业务任务，同时不伤主库、不泄露敏感数据、不让模型直接修库。

具体补什么
  • 只读连接、Query Guard、扫描/超时/并发预算
  • Schema、统计、慢 SQL、等待、告警、变更、拓扑工具
  • Query ID、新鲜度、Explain/Preview 和稳定错误合同
做到什么程度

PG-first 通过真实负载保护与故障注入；多引擎只复用合同，方言、权限、诊断和评测分别验收。

P1 · M4工具与动作网关
用户为什么需要

企业门户、ISV 和外部 Agent 可以安全复用问数与诊断，并把退款、Kill、改参数等高风险动作送进同一审批链。

具体补什么
  • 权威 API + Tool schema；Widget/CLI/MCP 做适配
  • 异步、取消、重试、幂等、配额和租户隔离
  • Propose → Preview → Approve → Execute → Verify
做到什么程度

内嵌与外部入口对同一用户返回相同权限和语义结果；写动作默认关闭，逐动作过风险 Gate。

P1 · M5工件、评测与运营
用户为什么需要

答案可保存、复算、分享和继续；产品团队能知道版本升级后哪些问题退化、哪一步失败、成本在哪里。

具体补什么
  • Answer / Query / Chart / Evidence Pack 等 Artifact
  • Trace、Eval、Benchmark、反馈、审计、成本和发布 Gate
  • 语义、Prompt、Tool、模型和执行版本关联
做到什么程度

一条真实任务可从用户问题回放到每个对象、策略、SQL、结果和动作；版本变更前后可自动回归。

BUSINESS-FIRST STORIES

数据库进入 Agent，不是只给 DBA 一个 Copilot

首批故事以业务价值排序。DBA 效率是必要能力，但真正推动客户购买的是收入、客户体验、风险窗口和产品上市速度。

P0 · 收入结算异常与经营损失控制

“华南支付成功率为什么从 99.2% 降到 96.8%，哪些商户和订单受影响，现在应先做什么？”

  1. DataArts 复用成功率、订单金额和商户分层口径
  2. PG 执行面查询实时订单与复制水位
  3. DAS/RDS 提供慢 SQL、等待、变更与拓扑事实
  4. AgentArts 组织影响清单、根因假设和处置提案
  5. 形成经营影响工件；扩容或改参数单独审批
客户为何付费缩短收入损失窗口，业务与技术不再各自排查
P0 · 客户体验退款激增与智能售后

“昨晚升级后，哪些 VIP 客户退款失败且工单超过 SLA？按已批准退款口径总额多少？”

  1. 统一订单、退款、客户和工单资产
  2. 语义合同锁定退款状态、时间和币种口径
  3. PG 安全联查当前状态，历史分析面计算趋势
  4. 生成客户分层证据包、建议回复和行动队列
  5. 退款、改订单、发消息进入独立 Action Tool
客户为何付费更快首答、更少误承诺、关键客户优先恢复
P0 · 管理风险变更前业务影响预演

“这个索引和参数变更会影响哪些高价值业务？窗口内是否可执行，失败如何回滚？”

  1. PG 获取 Schema、统计、负载与 Explain 证据
  2. DataArts 把表与业务域、Owner、关键指标关联
  3. 策略平面判断数据级别、窗口与审批人
  4. 生成影响范围、成本、验证指标和回滚计划
  5. 审批后执行，自动对比业务与数据库指标
客户为何付费把技术变更风险翻译成业务风险，减少重大事故
P1 · 客户产品SaaS 内嵌数据智能

“让我们的每个租户在自己权限下问经营数据，并能把答案保存为报告，需要重建什么？”

  1. 伙伴传最终用户、租户、用途和对象上下文
  2. 统一语义和 PG Query Guard 在服务端执行
  3. 异步任务返回结构化结果、引用和 Artifact
  4. 伙伴 UI 只负责体验，不复制策略和 NL2SQL
  5. Trace、配额、成本、SLA 按租户运营
客户为何付费更快把数据智能卖给自身客户，不承担全套治理成本

EMBEDDED VS EXTERNAL

能力同源，入口上下文与集成责任不同

最重要的原则是：入口不成为第二套事实和权限系统。内嵌体验靠上下文取胜；外部 Agent 靠标准合同、最终用户身份和稳定状态取胜。

RDS / DAS 内嵌

数据库上下文最深

  • 自动带入实例、数据库、告警、SQL 和时间窗口
  • 原生展示 Explain、拓扑、负载预算与动作预演
  • 适合业务影响诊断和高风险动作审批
独特点：专业执行面与深链
DataArts 内嵌

语义与分析工件最完整

  • 自动带入资产、指标、Owner、血缘和 Dashboard
  • 最适合自然语言分析、领域治理和内容发布
  • 数据库执行通过权威工具调用，不复制连接逻辑
独特点：领域语义与工件生命周期
企业门户 / Widget

业务流程最贴近

  • 带订单、客户、工单等业务上下文
  • 服务端仍执行 OBO、策略、查询与审计
  • 适合客服、运营和企业统一工作台
独特点：业务对象与人机协同
外部 Agent / Tool API

组合能力最强

  • 调用方负责会话、异步、取消、重试和 UI
  • 必须传最终用户、租户、用途与幂等键
  • 返回任务状态、Artifact、证据、错误和深链
独特点：跨系统组合且不泄露底层权限

G1–G6 VALIDATION

先证明一条链，再讨论全产品路线与 OKR

每个 Gate 都有停止条件。公开文档、原型和局部 Demo 不能替代目标账号中的端到端证据。

G1 · 对象连续性

同一对象能否跨产品引用

选择一个 PG 数据域，验证 DataArts 资产/指标、Agent 任务、DAS 查询和最终 Artifact 的 ID、版本、Owner 与深链。

不过：统一产品叙事不成立
G2 · 身份与权限

最终用户权限能否落到 PG

覆盖浏览器用户、服务身份、外部 Agent、权限撤销、越权字段与审计关联。

不过：只能停留在封闭内嵌场景
G3 · 语义与正确性

同一口径能否跨入口复用

建立真实问题、可信 SQL、严格结果真值和语义版本变更回归，比较 DataArts、DAS 和 API 结果。

不过：不能承诺业务问答产品
G4 · 工具与动作

权威能力合同是否可复用

验证查询、诊断、Artifact 和一个低风险动作的 API/Tool、异步、取消、幂等、预演、审批与验证。

不过：外部 Agent 只提供只读查询
G5 · 运营与保障

一条任务能否完整回放

打通 Task ID、对象、策略、SQL、Query ID、结果、Artifact、Eval、Audit、Cost，并注入超时、撤权和工具失败。

不过：不可规模化发布
G6 · 商业与组织

客户是否为完整旅程买单

用设计伙伴基线、可量化业务结果、WTP、采购路径、RACI、SLA 和成本模型选择产品归属。

不过：缩为能力包或专业工作台

FOUR OWNERSHIP OPTIONS

G1–G6 决定选哪条路

当前只优先验证 C，不预设最终选择。四个选项都必须解释统一入口、共享控制面和领域能力由谁承担。

A

数据库独立新产品

适合跨产品对象、身份和语义确实无法复用，且客户主要为数据库工作流付费。

最大风险：重复建设治理、BI 和 Agent
B

DataArts 主导迭代

适合 DataArts 能承接统一入口、语义、工件和外部工具，数据库只需提供高质量执行能力。

最大风险：数据库深度和高风险动作被弱化
C · CURRENT HYPOTHESIS

双平面联合产品

三个领域权威共享对象、身份、任务和证据；以一条客户旅程而不是一个组织边界对外。

最大风险：跨团队 RACI、SLA 和发布节奏
D

联邦能力包

不建设统一总入口，以标准 Tool/API、身份、Artifact、Trace 与评测包嵌入各专业产品。

最大风险：客户旅程继续碎片化
