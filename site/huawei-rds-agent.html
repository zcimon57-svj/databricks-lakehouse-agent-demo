故事的真正价值：不是 AI 替代客服或 DBA，而是把现有云服务组织成一条可验证、可复用、可对外提供的客户工作流。

产品方向

保留底座，打通断点，新增闭环

方向代号“RDS 受治理智能层”是本研究建议，不是华为云现有产品名称或发布承诺。

直接复用

数据库与云服务地基

  • RDS SQL / HA / Backup / Replica
  • DAS 慢 SQL / 诊断
  • DRS 全量 / 增量同步
  • DataArts 目录 / 质量 / 数据服务
  • 智能体编排、IAM、APIG、CTS
重点打通

从组件变成一条路径

  • 最终用户身份 → 数据策略
  • RDS / DRS / DAS 统一资产与时间线
  • 目录策略 → 实际查询强制执行
  • DRS 水位 → 答案新鲜度
  • UI / Widget / API 权限结果一致
必须新建

五个产品化服务

  1. Agent Policy Adapter
  2. Semantic Contract Service
  3. Query Gateway / Governor
  4. Trusted SQL + 双方言包
  5. Evidence + Benchmark / Monitor
不复制 Databricks 全栈：RDS 保持交易与数据库专业能力；新增层只负责把治理、语义、安全执行、Agent 与质量闭环串起来。

目标架构

三个查询路径，一个权威合同

实时窄查走只读实例；跨域历史走 DRS 分析副本；运维诊断走 RDS/DAS/日志 API。三条路共享身份、语义、证据与评测。

A · 实时

RDS 专用只读实例

单订单、当前状态、小结果；必须返回复制延迟并限制负载。

B · 历史

DRS → 分析副本

跨 MySQL/PG、长窗口、大聚合；必须处理水位、Schema 演进和失败。

C · 推荐

按问题混合路由

路由可解释、可配置、可评测，不能由模型随意选择数据库。

客户场景

先卖结果，不卖“一个大模型”

前三项可在只读边界内形成首批产品包；SaaS 内嵌和多租户运维价值高，但需要更成熟的身份、配额与隔离。

P0 · RDS ENTERPRISE ADD-ON

DBA Copilot

在 RDS/DAS 控制台把指标、慢 SQL、日志、告警、变更和 Runbook 组织成事故证据包。

目标：首个证据包 ≤5 分钟，MTTR -30%
P0 · INDUSTRY TEMPLATE

智能售后

联查订单、退款、客户、工单与 SLA；给解释和建议，不直接退款或改订单。

目标：首次取数/答复时间 -50%
P0 · DATA AGENT WORKSPACE

受治理业务问答

运营与财务在本人权限下使用统一指标和可信 SQL，减少临时取数与口径争议。

目标：转研发率 -30%
P1 · DEVELOPER PACK

SQL / Schema 助手

解释 Schema、生成受控只读查询并结合 DAS 诊断优化建议。

边界：不直接执行 DDL/DML
P1 · EMBEDDED DATA AGENT

SaaS 内嵌

API、SDK、Widget 提供租户隔离的问数能力，避免每个 ISV 重建 NL2SQL 与审计。

前置：on-behalf-of + 配额 + SLA
P2 · FLEET OPERATIONS

MSP / 集团多实例运维

跨账号汇总容量、风险和事故模式，但绝不使用共享高权限账号。

前置：跨租户隔离和委托审计

双引擎不是一个 Prompt

MySQL 做售后，PostgreSQL 做工单与运维证据

共享产品框架，但技术元数据、SQL 方言、权限、审计和性能基线分别建设与验收。

90 天落地

每两周交一份可判定证据

Gate 是停止条件，不是汇报标题：没有安全路径，不做真实数据；没有语义真值，不发布 Agent；没有业务改善，不扩外部 API。

G0 · W0–2

价值合同

3 家伙伴、Top 30 问题、基线、Owner、分析只读。

G1 · W3–4

安全路径

双方只读、DRS PoC、Query Gateway；危险查询全拒绝。

G2 · W5–6

治理闭环

资产、分类、策略与最终执行绑定；暴露字段覆盖 100%。

G3 · W7–8

语义真值

10–15 视图、15–25 指标、≥50 Golden Questions。

G4 · W9–10

证据 Agent

内嵌原型与 Widget；答案都带 SQL、来源和水位。

G5 · W11–13

伙伴试点

3–5 隔离租户；至少两家达到业务改善目标再继续。

建议目标，不是实测承诺

上线验收看正确、安全和业务结果

“回答很流畅”和“调用量很高”不能证明数据 Agent 可用；数字答案必须先验证结果与权限。

安全0

分析面生产写入、高严重度越权与敏感泄露

治理100%

暴露字段有 Owner、分类、策略；回答展示新鲜度

质量≥85%

≥50 个 Golden Questions 的 MVP 严格结果正确率

执行≥95%

受控 SQL 执行成功率；失败有稳定错误契约

体验≤8s

窄查询 p95；混合跨源建议目标 ≤30s

业务-30%

DBA MTTR；客服首次答复建议目标 -50%

内嵌 vs 外部 Agent

能力同源，集成责任不同

一套服务端 Capability Contract，三个入口做身份、语义、权限、结果一致性回归。

RDS / DAS 内嵌

上下文最完整

  • 自动带入实例、告警、时间窗口
  • 原生展示指标、SQL 和深链
  • 最快形成 DBA Copilot
企业 Widget

最贴近业务流程

  • SSO + 订单/客户上下文
  • 适合客服、运营与统一门户
  • 仍由服务端执行权限
API / Agent Tool

组合能力最强

  • 调用方传最终用户、租户和用途
  • 负责异步、取消、配额、重试
  • API Key 不能替代最终用户权限
ACTION GATEWAY

写动作单独治理

  • 提案、预演、影响范围
  • 审批、幂等、执行、验证
  • 退款 / Kill / 改参数不直连

GO / NO-GO

什么条件下值得立项

立项重点不是模型选型，而是设计伙伴、只读路径、业务 Owner 和跨产品小队是否真实存在。

查看 Epic、团队、风险与官方来源
GO
  • ≥3 家设计伙伴提供问题和基线
  • 双引擎有隔离只读/分析路径
  • 领域 Owner 负责指标和可信 SQL
  • DataArts/IAM 策略可落到执行层
  • 接受 MVP 只读和六个 Gate
STOP / SHRINK
  • 目标只是快速做聊天 Demo
  • 只能使用共享高权限账号
  • 无口径 Owner 或无安全查询路径
  • 要求 MVP 自动退款或修库
  • 成功指标只有调用量
