本轮尚无经授权的华为云、Databricks 或其他厂商账号级控制台验证。因此，公开页面之外的可见菜单、实际权限继承、端到端成功率、区域/Edition 可用性、配额、账单、性能、失败行为与支持流程均不能标记为“实际观察”。

2. 验证前置条件

任何账号级验证开始前必须同时满足：

  1. 用户另行明确授权具体云账号、Region、Edition 和可执行动作；本任务书本身不构成授权。
  2. 只使用隔离 Sandbox、平台样例或合成数据；不接入客户/公司数据和生产数据库。
  3. 每个测试用户使用单独、最小权限身份；不读取、复制或展示 Cookie、密码、Token、AK/SK。
  4. 默认只读。创建 Sandbox 资源、开启公测、产生费用、修改权限或执行数据库动作均需单独批准。
  5. 预先设置费用上限、资源清理 Owner 和终止时间；清理也是外部写操作，须在授权范围内。
  6. 截图和日志在进入报告前去除账号、项目、Region 内部标识、端点、凭据和业务数据。

如果任一前置条件不满足，保留 Unknown，不得用营销材料、其他 Region 或个人账号猜测补齐。

3. 五个验证 Gate

G1：产品骨架与对象贯通

要回答： DataArts 是否已有可持续演进的共享对象骨架。

在获得授权后，选择同一 Region、明确 Edition 的隔离项目，以一份合成订单数据验证：

  1. Studio 创建/登记的数据连接、表、目录、业务术语、质量规则能否被 Insight/Fabric/LakeFormation 通过稳定 ID 发现；
  2. 是否需要重复创建连接、上传驱动、复制凭据、重新描述字段或重新授权；
  3. Schema/字段/指标修改后，哪些下游对象自动更新、失效、告警或要求重同步；
  4. UI 和 API 返回的资源 ID、Owner、版本、Region、状态是否一致；
  5. 是否有导出、导入、版本、Review、发布、回滚和影响分析。

通过证据： 一张真实对象关系图、脱敏 API 响应、变更前后记录、每个重复配置点和明确的产品 Owner。

停止条件： 需要生产连接、长期凭据、收费开通或无法隔离的数据时立即停止并请求授权。

G2：身份、权限与入口一致性

要回答： “同一个助手”在 UI、API、iframe 和 Agent 中是否真的是同一安全边界。

合成数据至少包含：公开列、敏感列、两组互斥行、不可访问表。创建 A/B 两个最终用户和一个受限服务身份，执行同一问题矩阵：

测试 UI NL Query API iframe/Ticket 外部 Agent/MCP（若可用） 期望
允许的行/列 必测 必测 必测 必测 结果一致，审计主体为真实用户或明确服务身份
禁止的行 必测 必测 必测 必测 不在建议、SQL、结果、缓存或错误中泄漏
掩码列 必测 必测 必测 必测 所有路径遵守同一策略；任何明文路径立即阻断上线
无权表 必测 必测 必测 必测 明确权限不足，不返回空值伪装成功
转发/过期 Ticket 不适用 不适用 必测 不适用 过期拒绝；转发风险可控且可审计
服务身份 不适用 必测 视模式 必测 数据范围被明确展示，不冒充最终用户

通过证据： 每个入口的身份链、策略决策、Query ID、审计记录和负例结果。

安全否决： 任一路径能读取无权行/列、掩码明文或绕过数据库 RLS，则 G2 不通过。

G3：业务问数的正确性与持续运营

要回答： 能否从 Demo 走到可回归的业务产品。

使用合成订单/退款/库存/财务数据建立最小 Ground Truth：

  • 20 个直接指标问题；
  • 20 个 Join、时间、状态、币种与去重问题；
  • 10 个歧义/需澄清问题；
  • 10 个权限负例；
  • 10 个数据过期、空结果、大结果、超时和无效 Schema 问题；
  • 5 条多轮任务链与 5 条越界/Prompt injection 场景。

对每个样本保存：问题、期望口径、Golden/parameterized SQL 或结果、允许误差、数据快照、身份、实际 SQL、实际结果、Trace、延迟、费用、失败类别和评审结论。然后分别修改模型、Prompt、Schema、语义和权限，运行回归。

通过条件不是单一“准确率”：

  • 权限负例零泄漏；
  • 确定性指标命中可信资产或结果等价；
  • 歧义可澄清，不静默猜测；
  • 失败有机器可识别状态和 Trace；
  • 版本变更可比较、阻断、回滚；
  • BadCase 有 Owner 和修复后回归证据。

G4：数据库原生调查与动作安全

要回答： 哪些能力必须由数据库产品提供，以及能否安全供 DataArts/Agent 使用。

在合成 PostgreSQL/MySQL 类 Sandbox 中构造：慢查询、锁等待、连接耗尽、复制滞后、计划变化、失败 DDL 和过期统计。分三层验证：

  1. 只读调查： 元数据、实时状态、计划、日志、指标和查询历史能否关联到同一事件；
  2. 业务关联： 上层是否只通过脱敏证据 ID 将 DB 事件与订单/收入等指标关联；
  3. 动作： KILL/限流/参数/索引/DDL 只生成草案，静态校验和风险分级后进入人工审批；执行需要幂等键、超时、审计和后置验证。

必测失败：主库负载过高、只读副本滞后、扫描预算超限、取消、权限撤回、Agent 重试、重复提交、审批过期、动作后验证失败。

安全否决： Prompt 是唯一护栏、上层持有长期高权凭据、没有取消/预算、写操作无需明确确认、无法关联执行人与 Query/Order ID，任一成立则 G4 不通过。

G5：商业、运营与客户付费

要回答： 哪个产品归属能规模销售，而不只是技术可行。

需要三类证据：

  1. 产品运营： Region/Edition/GA、配额、计量、账单、SLA、升级/降级、数据保留、故障和支持 Owner；
  2. 客户旅程： 首次开通、接数、首个可信答案、分享/嵌入、月度运营所需人数与时间；
  3. 需求验证： 对目标客户分别测试经营问数、售后联查、财务证据、DB 故障和 SaaS 嵌入五类任务，记录现有替代方案、迁移成本、愿付费主体和否决条件。

官方案例只能证明案例中公开的流程，不能替代目标客户访谈、报价或试点数据。
