01

Snowflake · CoWork

最像“个人工作 Agent”的统一入口；不只问数，还把工件、自动化、搜索和跨系统动作放进同一工作面。

91.3 / 100动量 10.0±3

用户从哪里进去

公开入口是 ai.snowflake.com。CoWork（原 Snowflake Intelligence）定位为每位知识工作者的个人 Agent，并把 Deep Research、MCP 动作、可复用 Artifacts 与自动化放在同一首页。

CoWork 首页→自然语言目标→自动选择数据/工具→报告/图表/动作→Artifact / Automation

为什么当前排第一梯队

强项入口不是一个 BI 聊天框，而是数据、研究、工件、工具和后台自动化的统一工作壳；角色、caller grants、Agent identity、版本、评测和 trace 组成目前公开证据最完整的保证面。
残差Agent evaluation 目前不实际调用 MCP 工具；部分个人记忆、Skill、文件输出与 Agent Studio 能力仍处于预览或“soon”，不能按 GA 满分理解。
看图后的判断它在“从答案继续做事”上明显领先纯对话式 BI，但必须继续核验默认 role、跨系统 consent、外部动作沙箱和多方审批。

02

Databricks · Genie One

最像“受治理数据消费首页”：Ask/Search、Dashboard、Genie Space、App 和 Domain 围绕同一数据平台汇聚。

90.6 / 100动量 9.8±3

用户从哪里进去

获授权的业务用户可通过工作区内 Genie One 或直接 /one 进入。它不是替代专业工作区，而是给消费者一个简化入口，让用户搜索资产、自然语言提问、打开 Dashboard/Genie/App。

Genie One→Ask / Search→路由到资产/Genie→SQL/图表/答案→保存/分享/外部调用

数据建设与管理面

官方另提供 Lakeflow Connect 数据库/SaaS/文件/流接入、Unity Catalog 下的外部数据库联邦只读、Auto Loader Schema 演进，以及 Discover/Catalog Explorer、自动血缘、质量监控和敏感分类。它的强项是对象与治理底座连续；但公开材料没有证明这些专业配置都已由 Genie One 单一对话直接完成。

为什么与 Snowflake 并列第一梯队

强项入口背后是 Unity Catalog、metric views、Dashboard、Genie、MCP 和评测逐步围绕同一对象面收敛；看起来简单，但治理深度比“首页有聊天框”重要得多。
残差复杂业务/数据库写动作并非其当前强项；Genie Agent API、外部数据源、部分托管 MCP/OBO 和新入口能力仍有 Beta/Preview，嵌入的 viewer/publisher 凭据路径也不完全同构。
看图后的判断Databricks 更像“统一数据消费入口”，Snowflake 更像“统一个人工作 Agent”。两者 0.7 分差不具有实质排名意义。

Google Cloud · BigQuery Conversational Analytics

官方动图显示 Conversations 与 Agent Catalog 双面：用户可直接分析，也可发现、创建、发布领域数据 Agent。

85.9 / 100动量 9.8±4

用户从哪里进去

入口位于 BigQuery 的 Conversational Analytics，顶层包含 Conversations 与 Agents/Agent Catalog。用户可以进入已有 Agent 对话，也可由数据团队创建并发布领域 Agent；API v1 已提供程序化消费路径。

BigQuery→Conversations / Agents→选择 Agent/数据→多步推理与查询→回答/引用/API

强弱判断

强项结构化、非结构化、多模态、预测与 API/ADK/MCP 组合强，调用用户的数据权限有明确 IAM 路径；动画直接展示“不是一次 SQL 问答”的多步分析形态。
残差BigQuery、Looker、Knowledge Catalog 与数据库 Agent 分布在多个产品面；v1 API 与 UI 并不完全同构，例如官方曾明确 API 不返回 chart。
路线信号Google 更可能由 Gemini Enterprise 做上层分发、由 BigQuery/Looker/数据库 Agent 做领域执行；统一语义与策略是否真正跨产品仍要验证。

AWS · Amazon Quick

官方文档直接把 Chat 定义为 primary interface；从问答、Research 到 Flow、Space 和外部动作都由它首跳。

85.0 / 100动量 9.3±4

用户从哪里进去

用户从 Quick 首页聊天开始。系统可根据请求回答连接数据、生成内容、执行 Flow、开展 Research 或在外部应用中采取动作；Spaces 组织 Dashboard、Dataset、文档、知识库与连接器上下文。

Quick Chat→Agent / Space→数据/文档/Apps→Research / Insight / Flow→Consent 后动作

强弱判断

强项“对话是主入口”最明确；连接器、remote MCP、READ/WRITE consent、identity propagation、活动流和 sandbox 让它更像工作 Agent，而不是 BI Copilot。
残差Quick 是近年重新组合的产品面，长期对象稳定性、成本、规模与数据正确性回归证据仍不如 Snowflake/Databricks 完整。
看图后的判断AWS 在入口和动作上很强，但其治理优势更多来自跨服务身份与策略体系；若只看分析语义和可复现性，不应自动排在数据云双强之前。

Microsoft · Fabric Data Agent

作者在 Fabric 建 Agent，业务用户更可能在 Microsoft 365 Copilot/Agent Store 消费；入口优势来自办公分发，而非 Fabric 首页收敛。

84.4 / 100动量 9.0±4

用户从哪里进去

数据团队在 Fabric 工作区创建 Agent、绑定数据源、配置指令、测试并发布；业务用户可在 Fabric 中使用，也可经 Agent Store / Microsoft 365 Copilot 分发。两层入口是 Microsoft 的真实设计，不应误读为一个 Fabric 聊天首页。

Fabric Workspace→Data Agent + 数据源→测试/发布→M365 Copilot / Agent Store→只读回答

强弱判断

强项Entra OBO、RBAC、Purview 审计与 M365 分发是独特组合；用户无需迁移到另一个陌生工作台，是“第三方/上层 Agent 做入口”的强样本。
残差Fabric Data Agent 当前以只读为主，并有结果尺寸、语言、数据类型等限制；Fabric、Foundry、Copilot Studio 等多 orchestrator 下的答案与授权一致性仍是风险。
看图后的判断作者界面清楚、可发布，但它本身不证明统一消费体验。Microsoft 的强项要在 M365 里判断，而不是拿这张 Fabric UI 与 Genie One 首页机械比较。

阿里云 · Quick BI + DataWorks Data Agent

业务消费面有智能小Q；数据建设面已出现对话式接入、ChatDB 与治理 Agent，覆盖范围明显不再局限于问数。

81.8 / 100动量 9.5±5

用户从哪里进去

业务消费从 Quick BI 顶部“智能小Q”进入；数据建设则从 DataWorks AI Native / Data Agent 进入。最新官方 DI Agent 文档明确把单表/整库、离线/实时同步做成自然语言任务，并提供 ChatDB 与多模态 ETL；治理 Agent 位于 DataWorks 治理场景。公开资料仍未证明这些入口共享同一 Session、OBO 与 Trace。

智能小Q / Data Agent→消费问题或数据任务→数据集 / 数据源 / 治理上下文→答案 / Pipeline / 治理计划→确认 / Skill / CLI / DMS

数据建设与管理面

DI Agent 官方说明可自动探测 Schema、字段映射、资源和调度，展示表清单与配置摘要后发布；还可画像已接数据源、预览样例、建库建表和修改结构。Data Governance Agent 可扫描、生成治理方案与 SQL Diff，用户确认后修复并复检。能力很激进，但写操作必须额外验证最小权限、影响分析、幂等和权威后验。

强弱判断

强项中文业务入口完成度高；DataWorks 已把接入/开发/治理任务显性 Agent 化，Quick BI v6.2 又提供外部 Skill/CLI，DMS MCP 覆盖数据库工单与审批。
残差Quick BI、DataWorks 与 DMS 仍是多条产品线。公开资料没有证明它们共享同一最终用户委托、语义对象、策略决策 ID 和端到端 trace；连接器“80+”也不等于每种源/动作同等成熟。
修正后的判断阿里在“对话建接入/治理任务”的显性程度已构成直接追赶压力；华为要领先，必须把消费、建设和 DB 证据做成同一线程，而不是复制三个入口。

腾讯云 · DataBuddy

方向最激进的国内新入口：不是给旧数据平台加一个问数框，而是把工程、治理、分析都声明为“对话即交付”。

79.6 / 100动量 9.8±7

用户从哪里进去

用户进入 DataBuddy 工作空间，从首页直接描述任务；侧栏把数据、知识库、任务开发、工作流、SQL 分析、仪表盘、治理、模型与服务放在同一壳层，输入框可选择 Agent、模型与 Skills。

DataBuddy Workspace→自然语言任务→Agent + Skills→SQL/工程/治理/分析→报告/发布/人把关

强弱判断

强项官网将统一元数据、语义层、细粒度权限、MCP 和三类 Agent 组合在一起；DatabaseClaw 又公开 OBO 强绑定、独立 AI role、L1–L4 风险等级与审计。
残差产品在 2026-08 基准日前后刚发布，官网架构、FAQ 与 UI 截图的证据密度高于规模化客户、区域、Edition、SLA、回归评测和持续运营证据。
看图后的判断它的产品形态比华为当前公开组合更接近目标终局，但 ±7 的不确定度意味着不能把“发布得新、讲得完整”直接等价成“已经比成熟产品稳定”。

Oracle · Analytics AI Agent

入口并不最统一，但它在“外部 Agent 如何以最终用户身份安全进入数据库”这个子问题上是关键标杆。

79.0 / 100动量 8.7±5

用户从哪里进去

作者在 OAC 中为 Agent 绑定数据集、补充指令、首条消息与知识文档，再把 Agent 加到 Workbook；消费者在 Workbook Insights/Assistant 中使用，也可独立使用。Select AI、Database Tools MCP 与 OAC 仍是多个入口面。

OAC 创建 Agent→数据集/指令/文档→Workbook / standalone→自然语言分析→DB Tools / A2A

强弱判断

强项Oracle Database Tools MCP 的短期 OBO 可把最终用户身份带到数据库，并由数据库实施行、列、单元级安全；这是判断外部 Agent 数据授权的高价值参考。
残差OAC、Select AI、Database Tools 与 AI Data Platform 的入口、Agent 生命周期、路由、版本、评测和 trace 尚未形成 Snowflake 式的统一公开证据。
看图后的判断截图本身看起来不如 Genie One 统一，但不能因此低估 Oracle 的深层数据库授权；“入口漂亮”和“数据源最终授权强”是两个维度。

火山引擎 · Data Agent

专注数据分析与深度研究：入口已很像通用 Agent，但产品强项仍集中在分析、报告和嵌入。

68.6 / 100动量 7.8±6

用户从哪里进去

购买服务并进入数据智能体后，用户选择/创建项目，进入 Data Agent 对话页。通用 Agent 可切换研究、联网、拓展与文件输入；配置后的智能分析 Agent 可做问数、归因、深度研究并生成网页/文档报告。

数据智能体项目→Data Agent 对话→研究/联网/拓展→SQL/Python/知识→网页/文档报告

强弱判断

强项多数据集、语义模型、深度研究、步骤干预、报告编辑、JWT/iframe 嵌入与运营评测形成较完整的分析产品面。
残差分析面内的逐工具策略、最终用户 OBO、安全动作、Agent/语义/策略版本联动及数据库原生治理公开证据较弱。
看图后的判断首页形态与领先者相似，但“有研究/拓展按钮”不能直接证明跨系统受控动作。它更像高深度分析 Agent，而不是完整企业工作 Agent。

华为云 · DataArts Insight 智能分析助手

真实问答入口已经存在；差距不在“有没有聊天框”，而在它能否成为 DataArts、AgentArts 与数据库共同的统一任务壳层。

67.6 / 100动量 9.0±6

用户从哪里进去

用户先购买 DataArts Insight 企业版并申请智能分析助手公测开通，再创建项目、连接数据源、建数据集、创建并同步助手，最后从“数据分析 → 智能分析助手 → 问答”进入。它目前是项目内 BI 旅程，不是跨产品统一首页。

Insight 企业版/公测→项目 + 数据源→数据集 + 助手→问答→图表/见解

强弱判断

已经具备自然语言问数、图表与智能见解；产品介绍还公开评测管理与 BadCase。AgentArts 另有 Gateway、API→MCP、认证、Trace/Eval/版本回流，DAS/DWS 也有数据库 Agent/MCP 组件。
核心差距公开资料没有证明同一用户身份、指标/语义 ID、工具策略、Task/Artifact、Trace 和动作生命周期贯穿 Insight、Studio、AgentArts 与数据库。组件存在不能当作集成已完成。
看图后的判断当前页面视觉上比 Genie One 更“纯聊天”，但入口更窄、前置步骤更多。优先级应是贯通治理与委托控制面，而不是再造一个更漂亮的聊天首页。
