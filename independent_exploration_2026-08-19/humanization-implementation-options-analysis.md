# 内容整改选型：直接改写、Humanizer 与仓库级 Skill

> 状态：选型分析，不代表已经安装或运行任何第三方 Skill
>
> 快照日期：2026-08-21（Asia/Shanghai）
>
> 前置审查：[`content-humanity-and-readability-independent-review.md`](./content-humanity-and-readability-independent-review.md)

## 1. 结论

当前问题不应交给一个通用 `humanizer` 包办。

推荐路线是：

1. 由当前模型完成主要的语义和结构整改；
2. 把本仓库的读者、术语、证据和 HTML 验收要求固化成仓库级规则；
3. 只把高质量 Humanizer 当作末道文风检查表；
4. 用无前置上下文的读者测试证明文档真的更容易理解；
5. 小范围 A/B 验证后，再决定是否把外部 Skill 固定引入仓库。

也就是说，**自身能力足以完成整改，第三方 Skill 的主要价值是约束一致性和防止回退，不是替代对产品、证据和读者的判断**。

当前不建议直接安装第三方 Skill，更不建议把全文一次性交给 Humanizer 自动重写。

## 2. 为什么这不是一次普通的“去 AI 味”任务

独立审查确认的问题至少分四层：

1. **读者入口**：开篇没有先讲清楚谁遇到什么问题、产品做什么、结果是什么；
2. **术语身份**：行业术语、厂商名称、本文定义和组件占位名混在一起；
3. **证据表达**：设计分、推断和实际测量结果的视觉身份不够稳定；
4. **页面阅读**：超长卡片、密集矩阵和固定画布放大了理解成本。

通用 Humanizer 通常擅长处理的是第五层：套话、空泛形容词、重复结构、机械转折、销售腔和聊天机器人痕迹。它对前四层没有足够的仓库上下文，也不能自行判断 C0–C7、Goal Contract、Gate、Unknown 或产品候选名在本项目中的真实身份。

因此，如果把“AI 检测分下降”当作目标，可能得到更口语的文字，却仍然没有解决读者为什么看不懂的问题；还可能损坏事实、引用、术语和边界。

## 4. 对 `blader/humanizer` 的判断

它是目前最值得参考的通用候选，但不应成为主编辑。

### 4.1 值得保留的部分

- 明确要求保留每一项主张；
- 不允许凭空增加人名、数字、日期、引文和引用；
- 会根据正式、日常或技术文档匹配语气；
- 对免责声明、真实备选方案、复杂格式和引用提供误报保护；
- 文件模式要求保留代码块、YAML、数据和链接目标；
- 最终自检会再次确认事实、引用和排序是否发生变化。

这些规则与本仓库的事实、推断、建议和 Unknown 边界相容，可以作为改写后的保守检查表。

### 4.2 不能承担的部分

- 它不知道谁是本文的首要读者；
- 它不能判断某个术语是行业标准、厂商正式名称还是本文自造；
- 它不能决定主页面与专家附录怎样拆层；
- 它不能证明一个精确分数是否有足够证据；
- 它不负责 HTML 的响应式阅读和信息密度；
- 它的词表、句例和主要检测模式来自英文材料，对中文技术文档的效果尚无本项目证据。

### 4.3 “项目有测试”不等于“改写效果已经验证”

该仓库当前的 `scripts/validate-package.py` 检查版本一致、元数据、规则编号、README 列表、文件数量和行数等包结构条件。它没有提供本仓库可见的中文技术文档基准集、盲评结果或真实读者理解测试。

所以可以确认它是一个结构完整、规则谨慎的 Skill 包；不能据此确认它对这批文档一定有效。

## 5. 当前模型能做什么，仍需什么约束

当前模型有能力承担主要整改，因为整改需要的并不是替换若干词，而是同时完成：

- 从现有证据中重建一条业务任务故事；
- 保留事实、引用、Unknown 和安全边界；
- 给术语标注稳定身份，并补首次白话解释；
- 让业务入口、产品能力、研究证据和技术附录各自服务一种阅读任务；
- 让 Markdown 与 HTML 共用同一叙事层级；
- 对桌面端和手机端进行渲染复核。

独立审查已经展示了这种识别和判断能力。不过，仅靠一次对话中的自由发挥不够稳。仓库还需要一个可重复的本地合同，防止后续轮次重新出现名词堆叠、伪精确和卡片化过度的问题。

这个合同至少应包含：

1. 先指定首要读者、阅读后要做的决定和一条主任务；
2. 核心能力必须说明角色、问题、输入、动作、输出、失败和边界；
3. 术语必须标记为行业术语、厂商名称、本文定义、建议产品名、组件占位名或接口候选名；
4. 行业术语首次出现时补一句白话解释，本文定义使用“本文将……称为……”；
5. 不改变事实、数字、日期、链接、引用、证据标签和 Unknown；
6. 未经验证的精确分数不能承担首页主要说服任务；
7. 先改 Markdown 的信息架构，再生成或调整 HTML；
8. 文风检查只能在语义、结构和证据检查之后进行。

## 6. 推荐实施流程

```text
现有证据与审查结论
        ↓
读者、任务、术语和证据合同
        ↓
当前模型完成结构与语义整改
        ↓
保守 Humanizer 检查套话和机械句式
        ↓
事实/数字/链接/Unknown 差异检查
        ↓
无上下文读者测试
        ↓
桌面与手机 HTML 渲染复核
```

Humanizer 位于第四步，而不是第一步。

## 7. 先做小样，不直接全量改写

建议选两个代表性片段：

1. `README.md:36-42`：测试能否建立三分钟可理解的业务入口；
2. `huawei-catch-up-product-plan.md:1-110`：同时覆盖标题、开篇、术语、设计评分和 C0–C7 功能表。

比较三种输出：

- A：只按本仓库合同由当前模型整改；
- B：只按通用 Humanizer 规则整改；
- C：先做 A，再用 Humanizer 保守复核。

验收不能以“更像人写的”一句话结束，至少检查：

1. 无背景读者能否在三分钟内回答“为谁解决什么问题”；
2. 能否复述一条从输入到结果的任务；
3. 能否区分行业术语、厂商名称和本文自定义名词；
4. 事实、数字、链接、引用、排名、证据标签和 Unknown 是否完全保留；
5. 是否出现新造事实或过度口语化；
6. 专业读者是否仍能找到接口、Gate 和验证依据；
7. 手机端是否无需横向拖动即可理解主叙事；
8. 通用 AI 文风模式是否减少。

只有 C 稳定优于 A，才值得把 Humanizer 固定引入仓库。若 A 与 C 相当，就保留更小、更可控的仓库级规则，不增加第三方依赖。

## 8. 安装与安全边界

本次只做远程只读检查，没有克隆、安装、运行或提交任何第三方代码。

如后续决定试用：

- 固定到已审查的 commit，而不是跟随 `main`；
- 优先使用项目级 Skill，不做全局安装；
- 首轮只读取纯 Markdown 指令，不执行第三方脚本；
- 禁止把内部材料提交给外部 API 或“检测规避”服务；
- 先在副本或小样上运行，检查事实差异后再触碰正式产物；
- 许可证不清楚的 Skill 只借鉴公开方法，不复制或打包其内容。

## 9. 最终决策

现在不安装高星 Humanizer，也不把全文交给通用规则重写。

下一步最稳妥的是：由当前模型依据已经持久化的独立审查，先完成两个片段的小样；把 `blader/humanizer` 的保真和反 AI 套话规则作为第二遍检查；再用无上下文读者和渲染结果决定是否推广。

若小样通过，再创建一个很小的仓库级 Skill，名称和职责应围绕“面向读者的技术产品文档”，而不是笼统的“humanizer”。

## 10. 本轮实施结果（2026-08-21）

本轮已在分支 `docs/reader-first-optimization` 采用方案 A：由当前模型依据仓库上下文完成结构与语义整改，没有安装或运行第三方 Humanizer，也没有把材料发送给外部服务。

实施范围包括：

- 新增一页读者指南，用一条退款率分析任务解释目标产品和研究结论；
- 新增 [`reader-first-editorial-contract.md`](./reader-first-editorial-contract.md)，把读者、术语、证据、分层和 HTML 验收要求固化为仓库规则；
- 重写研究索引、综合结论、治理专题、验证合同和产品方案的入口层；
- 明确 C0–C7、五个平面、Goal Contract、Gate 等名称的身份和白话含义；
- 将精确评分、能力矩阵和技术细节降为可展开的专家附录；
- 重构四份独立 HTML 的首屏、导航和手机阅读提示；
- 让生成页使用单一主标题和针对页面内容的导语。

机器验证结果：16 个页面分别在桌面和手机视口检查，共 32 次；HTTP、UTF-8、图片、锚点、站内链接、脚本错误和页面横向溢出均无失败。改动前已经存在的外部证据链接没有删除；按文件去重统计，共保留 226 个链接条目。桌面与手机首屏也完成了人工截图复核。

通过把评分、矩阵和技术章节移入可展开附录，三个主 HTML 在桌面端的默认页面高度分别从 26,721、18,168、18,350 px 降为 19,307、14,140、11,059 px，约减少 28%、22% 和 40%；手机端产品方案与竞品主报告分别约减少 31% 和 23%。内容没有删除，锚点进入折叠章节时会自动展开并定位。

仍未完成的验证是：让完全不了解项目的人在无背景条件下复述目标产品、主任务和术语身份。因此，这次结果可以确认结构、证据和渲染没有明显回归，但不能替代真实读者测试。若下一步实测仍暴露机械句式，再对具体片段做 Humanizer A/B，而不是全量自动改写。
