Conversation-first · Capability-first · Harness-first · 2026-08-20

先定要做成哪些产品能力，
再选两种架构。

产品首先要回答“用户能用一句话做成什么、先做哪几件”。首期串起数据接入与资产化、智能问数与分析、数据知识构建、数据库洞察，再比较公司级协作与数据库绿地两套承载方案。

当前建议技术按数据库绿地方案立即启动；组织给公司协作方案 2–4 周 Gate。条件成立时，同一代码直接升格，不推倒重来。

01 · Product capabilities

先决定产品让用户“一句话做成什么”，再讨论 Agent 怎么做。

产品目标不是 Goal 状态机，而是一组客户能理解、购买和持续使用的能力。首期覆盖接入数据、生成资产、管理和使用数据，再做深数据库洞察；不把调用协议当成产品卖点。

DATA INTELLIGENCE · 数据智能

一句话接入、生成、管理和使用数据。

一个对话 Agent、十种回答工件。用户只描述要完成的事情，产品自动路由能力，不要求选择 Dashboard、Harness、模型或内部 Agent。

接数据 · 比较直查/导入/定时/CDC，生成 Pipeline生成产品 · 得到清洗表、指标、知识、质量和血缘草稿管数据 · 得到发现、影响、任务与可审核治理 Diff问数/分析/查库 · 得到表图、证据、结论与诊断
C0P0 核心 1

数据接入与准备

“维表直查、交易表 CDC，再导入这批供应商文件。”

比较直查/一次/定时/CDC，完成连接、Schema/映射、质量/敏感预检、发布与数据到达验证。

交付：接入方案 · Pipeline 草稿 · Schema Diff · 水位/验证
C1P0 核心 2

智能问数

“最近 30 天华东各地区退款率是多少？”

理解口径、消歧、多轮追问、生成并执行安全 SQL。

交付：表 · 图 · SQL · 参数 · 口径 · query_id · 证据
C2P0 核心 3

智能分析

“哪些地区显著上升？为什么？影响多大？”

完成趋势、对比、分群、异常、贡献和假设验证，区分事实与推断。

交付：分析画布 · 关键发现 · 证据 · 可复算报告
C3P0 核心 4 · 草稿

数据知识构建

“扫描订单库，生成客户 360 和知识网络草稿。”

从 Schema、样例、文档和血缘生成清洗表/视图、指标语义、实体关系、质量规则与 Verified 候选。

交付：数据产品蓝图 · 知识网络 · 语义/规则草稿 · Review
C4P0 · DB 差异化

数据库洞察

“订单库昨晚为什么变慢？”

查询实例、容量、Top SQL、锁、等待、计划、指标和变更，形成证据调查。

交付：体检/调查报告 · 时间线 · 候选原因 · 建议
C5P0 发现 / P1 闭环

智能治理

“检查敏感、质量和血缘，给我修复计划。”

P0 完成资产发现、分类/质量/血缘候选和可审核计划；P1 扩跨源策略、生命周期与受控修复。

交付：资产清单 · 覆盖报告 · 影响图 · 待审批 Diff
C6P1 少量 / P2 扩展

安全行动

“取消异常查询，并确认业务恢复。”

形成动作方案，经策略和人工审批后幂等执行，从权威系统验证结果。

交付：审批 · 执行 · 后置验证 · 补偿/回滚证据
C7P2

主动智能

“每天监控退款率，异常时自动分析并通知我。”

由指标、质量或数据库事件触发调查、解释、订阅和下一步建议。

交付：主动洞察 · 告警调查包 · 周期报告 · 动作草案
“一句话建知识”不是让模型随意画图。产品构建的是可治理的数据知识网络：实体、表、指标、维度、规则、Owner、Verified Query 及其业务关系、Join、血缘、派生和影响。推断关系必须带来源、置信度和 Review 状态，首期只能生成草稿，不能自动发布。

Focus first

首期集中四条主线，用一条纵向故事串起来。

主线 A · 首次价值

接入 + 资产化

一句话比较直查/导入/定时/CDC，完成 Schema、质量/敏感预检和数据到达验证，再生成可用资产候选。

主线 B · 最大使用价值

智能问数 + 分析

找到正确数据与口径，安全查询并完成趋势、对比和贡献分析，交付表图、SQL 和证据。

主线 C · 准确率壁垒

数据产品 + 知识

生成清洗视图、指标、关系、质量规则和 Verified 草稿，经 Owner Review 后服务问数与治理。

主线 D · DB 不可替代

数据库洞察

一句话查实例、运行状态和慢 SQL/锁/等待/计划变化，形成证据时间线与处置建议。

Capability to build

每项产品能力都落到共用模块和原子执行域。

产品能力定义客户买到什么；功能模块组织完整旅程；原子域通过同一套 CLI/MCP 被 Harness 调用。三层不能互相代替，也不重复建栈。

02 · Data build & management

Responsibility split

Agent 自动化越强，责任边界越要在回复里看得见。

PRODUCT

产品负责

连通/能力/负载与四路径比较；Schema/Profile、映射、质量/敏感预检；版本化 Pipeline、停止/恢复、目标验证和资产草稿。

DATA OWNER

用户负责

批准身份、网络、用途、驻留、SLA、成本、主键和业务口径；裁决敏感等级、误报、Owner 与生产发布。

NEVER

禁止捷径

长期密码进 Harness；静默丢列或污染可信表；模型自报成功却无目标证据；自动发布推断血缘、指标或访问策略。

EVIDENCE

完成判据

源/目标身份、Schema 版本、行数/校验和或水位、坏数策略、Pipeline 状态和审批记录都能由权威接口复核。

03 · Choose scheme

能力组合和优先级明确后，再选两种完整产品架构。

方案差异不只是组织名称，而是接入/资产/治理做到多广多深、由谁承载、入口、Owner、硬依赖、首期部署和风险不同。顶部“全篇”切换会隐藏另一方案的架构、专属模块和路线内容。

C4 · Database insight

数据库洞察不是一个诊断 Skill，而是方案二的第一差异化产品能力。

它覆盖一句话查实例、查状态、做体检和调查故障。以“昨晚 22:00 后订单库为什么变慢”为例，Harness 组织假设，数据库权威工具提供计划、锁、等待、会话、指标和变更；相关性不能冒充已证实根因。

01绑定现场实例、引擎、版本、时间窗、时区、主体
02保全快照配置、拓扑、健康、数据新鲜度
03重建负载CPU/IO/内存/连接/复制时间序列
04定位贡献Top SQL、等待、锁链和会话
05对比变化计划差异、参数、发布、告警和运维事件
06验证假设时间对齐、替代解释、反证和证据缺口
07诊断工件事实 / 相关性 / 推断 / 建议分层交付
现场身份实例、版本、时间窗、时区、采样间隔与 freshness。
原始证据引用SQL hash、query_id、计划、等待、锁、指标和事件 ID。
诊断置信边界已证实事实、相关性、推断、替代假设与缺失证据。
可验证建议收益、风险、前提、验证方法；首期只给动作草案。

P0 · 全只读

快照、Top SQL、等待、锁、计划差异、时间线、相关性和调查报告。证据不足时明确下一步，不生成“确定根因”。

P1 · 极少受控动作

只在事故演练通过后开放取消指定 Query/Session；必须有审批、幂等、超时、权威后置验证和审计。参数、索引、扩容、切换继续关闭。

Shared conversation contract

十种回答共享一个对话壳，差别只在回复工件。

产品没有一排能力 Dashboard，也不把接入、导入、资产、治理、问数、分析、知识和数据库拆成多套页面。用户提问后，Agent 先用语言回答，再把本次最合适的 Pipeline、治理报告、图表、知识图、时间线或审批卡嵌入回复。

Delivery roadmap

两周跑通“接入—资产—问数—查库”，一月形成首个可用版。

每阶段按“客户能用一句话做成什么”验收，不按组件数量验收。这是待真实基线校准的建议，不是未经容量验证的承诺。
