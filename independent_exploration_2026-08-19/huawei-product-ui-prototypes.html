返回方案
Conversation-first · Product in action

一个对话 Agent，
十种结构化回答。

产品不是一组 Dashboard。用户始终留在对话中；接入方案、Pipeline、资产蓝图、治理报告、图表、知识图、诊断时间线和审批单，都是 Agent 回复消息里的可交互工件。

证据边界：以下是产品设计原型，不是华为云现网截图、已发布功能或交付承诺。样例数据均为合成内容；真实能力、正确率、性能、权限和接口仍需内部 Gate 验证。
对话 唯一主入口建设 接入 + 资产 + 治理回答 文本 + 结构化工件证据 折叠在回复附件动作 回复内审批
DATA 01 · C0/C5

接入现有数据库：先比较路径，再生成 Pipeline

用户描述业务目标；Agent 检查网络、权限、Schema 与增量条件，并解释哪些表适合直查、定时同步或 CDC。

回答形态回复内同时给路径比较、前置检查、表清单和可审核 Pipeline；不是把用户丢到连接器向导。
C0 接入与准备P0
用户目标维表不复制，交易表接近实时
Agent 运行身份/网络、Schema、主键、负载与 CDC 前置检查
回复工件四路径比较、表分配、Pipeline 草稿与缺口
可信边界前置未满足不发布；凭据不进入 Agent
DATA 02 · C0/C5

导入新数据：Schema、坏数和敏感字段先在回复中说清楚

用户上传文件或给出对象目录；Agent 先画像、映射和隔离异常，再生成一次导入或周期增量任务。

回答形态上传不是“成功/失败”两态；新列、类型冲突、坏行、PII、目标表和调度都可在发布前审阅。
C0 导入新数据P0
用户目标导入文件并建立每日增量
Agent 运行格式/Schema/Profile、质量、PII、映射与隔离
回复工件文件画像、字段 Diff、坏行和调度草稿
可信边界新列与敏感策略未确认前不写正式表
DATA 03 · C0/C3/C5

从现有库生成数据产品：直接告诉用户能做成什么

Agent 扫描存量数据库后，不只返回“有多少张表”，而是给出可生成的数据产品、知识、质量和服务化候选。

回答形态回复内是数据产品蓝图：每项交付物的来源、自动化程度、置信度、缺口、Owner 和发布条件一目了然。
C3 数据产品/知识P0 草稿
用户目标从已有库生成客户 360
Agent 运行资产扫描、关系/指标/规则候选与缺口识别
回复工件数据产品蓝图、置信度、Owner 与发布条件
可信边界自动化程度不冒充业务正确；Owner Review 后才发布
DATA 04 · C5

管理数据：发现、影响和修复计划都留在对话里

Agent 扫描敏感、质量、血缘和 Owner 覆盖，先给事实与候选，再把治理任务与变更 Diff 交给用户审核。

回答形态治理不是咨询报告的终点；回复同时生成可分派任务和修复草案，但未审批前不修改生产规则、表或权限。
C5 智能治理P0 发现 / P1 修复
用户目标扫描敏感、质量和血缘并排序
Agent 运行分类、规则、freshness、血缘与影响分析
回复工件覆盖度、问题清单、治理任务和 Diff
可信边界事实/推断分开；生产变更未审批不执行
ANSWER 01 · C1/C2/C4

综合回答：一句话得到今日经营简报

用户不选择能力菜单；Agent 自己判断需要查询经营指标、分析异常并检查数据库现场。

回答形态先给结论，再嵌入趋势图和重点事项；运行详情、来源和证据位于回复底部。
统一对话入口C1/C2/C4
用户提问今天经营上最需要关注什么
Agent 运行自动规划多次查询和数据库快照
回复工件结论、重点列表、趋势图与证据附件
可信边界异常原因不足时引导继续分析，不装作已证明
ANSWER 02 · C1

智能问数：回答中直接嵌入表格和图表

对话继续承载追问；SQL、口径、query_id 和权限证据折叠在同一条 Agent 回复下。

回答形态一句自然语言结论 + 一张主图 + 一张明细表；不把用户送到新的 Dashboard。
C1 智能问数P0
用户提问地区退款率是多少
Agent 运行语义解析、SQL Guard、预算、查询与结果校验
回复工件自然语言结论、趋势图、明细表与证据附件
可信边界回答只陈述数据事实，不擅自解释原因
ANSWER 03 · C2

智能分析：同一对话中的追问返回分析图

用户直接追问“为什么”；Agent 在回复里呈现分析计划、贡献图、事实、候选解释和 Unknown。

回答形态分析过程不是新页面，而是当前回复的可折叠运行记录和一张可复算分析工件。
C2 智能分析P0/P1
用户追问为什么上升，并排除规模效应
Agent 运行多步计划、查询、贡献回总和替代解释
回复工件贡献图、事实/推断/Unknown 与可复算报告
可信边界相关性不写成因果，缺失数据明确展示
ANSWER 04 · C3

数据知识构建：知识图是 Agent 的回复工件

用户一句话提出建知识目标；Agent 回复生成结果、冲突和审核请求，不把用户送到复杂建模工作台。

回答形态回复正文解释生成了什么，内嵌知识图；候选关系、来源和 Review 状态随图一起返回。
C3 知识构建P0 草稿
用户提问建立知识网络但不要自动发布
Agent 运行扫描、候选生成、冲突校验和影响分析
回复工件知识图、候选状态、来源、置信度和 Review 链接
可信边界回复只能生成草稿，发布仍需 Owner 审核
ANSWER 05 · C4

数据库调查：诊断时间线就在对话回答里

用户从数据库实例页或统一 Agent 提问都进入同一对话；Agent 返回证据时间线和候选原因。

回答形态先用自然语言回答“发现了什么”，再嵌入指标/SQL/计划/变更时间线与反证。
C4 数据库洞察P0
用户提问昨晚为什么变慢，要求证据
Agent 运行快照、Top SQL、锁/等待、计划和变更关联
回复工件诊断时间线、候选原因、反证和调查证据
可信边界相关性不冒充根因，P0 全只读
ANSWER 06 · C6 · P1

安全行动：审批卡也是 Agent 的一条回复

用户在调查对话里继续提出动作；Agent 返回动作合同和审批卡，未审批前不执行。

回答形态回复解释风险并嵌入一次性审批工件；执行后仍在同一线程返回权威验证结果。
C6 安全行动P1
用户追问只取消明确的阻塞会话
Agent 运行动作合同、策略、影响评估和审批请求
回复工件一次性审批卡、幂等键、执行与验证状态
可信边界未审批不执行；模型不能自己确认成功
